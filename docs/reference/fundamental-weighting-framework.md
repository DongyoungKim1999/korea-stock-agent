# 기본적분석 가중치 프레임

fundamental-analyst가 A8 단계(안정성/성장성/활동성 각 1~5점 산출)에서 따라야 하는 기준.
financial-ratio-analyzer의 출력(`relative_favorability` 등)을 이 프레임으로 점수화한다.

**점수는 카테고리마다 독립적인 1~5점 유리수** (소수 1자리 권장, 예: 3.4). 세 카테고리를 하나로
합산하지 않는다 — 안정성/성장성/활동성은 서로 다른 질문에 대한 답이라 합산하면 의미가 희석된다.

## 기본 공식

카테고리 내 지표들의 `relative_favorability`(financial-ratio-analyzer가 이미 "1보다 크면 유리"로
정규화해둔 값)를 **기하평균**으로 합친다 — 비율값은 산술평균이 아니라 기하평균으로 합치는 것이
통계적으로 맞다(2배 유리한 지표 하나와 0.5배 불리한 지표 하나가 있으면 산술평균은 1.25로 왜곡되지만
기하평균은 1.0으로 정확히 상쇄된다).

```
clamped_i = clamp(relative_favorability_i, 0.2, 5.0)   # 지표 하나가 카테고리 점수를 독점 못 하게 상한
category_favorability = geometric_mean(clamped_1, clamped_2, ...)
  (null 값은 제외; 전부 null이면 해당 카테고리는 "산출불가"로 보고하고 점수를 매기지 않는다)

ratio_for_log = max(category_favorability, 0.05)   # 음수/0 방어 (예: 영업손실로 이자보상배율이 음수인 경우)

score = clamp(3 + sensitivity × 2.16 × ln(ratio_for_log), 1.0, 5.0)   # 소수 1자리로 반올림
```

**왜 [0.2, 5.0]로 먼저 클램프하는가**: 전년 매출이 0에 가까운 초소형주는 매출성장률이 +23,900%
같은 허수로 튀고, `relative_favorability`(target/peer 비율)가 무계라 수백~수천 배가 될 수 있다.
클램프 없이 기하평균을 내면 이 지표 하나가 카테고리 점수를 5.0으로 독점해버린다(실사례: 41종목이
이렇게 허위 5.0점을 받았다). 지표별 기여를 최대 log(5)로 제한하면 이상값이 점수를 지배하지 못하고,
정상 범위(대개 5배 이내)의 비교는 그대로 유지된다. 아래 "지표 하나가 극단치인 경우" 예시 참고.

`2.16`은 "산업평균 대비 정확히 2배 유리하면 +1.5점, 절반 수준이면 -1.5점" 정도가 되도록 잡은
확산계수다(ln(2)≈0.693, 0.693×2.16≈1.5). 산업평균과 동일(favorability=1.0)하면 `ln(1)=0` →
정확히 3.0점(중립)이 된다.

## sensitivity (업종별 가중치 조정)

**모든 카테고리 `sensitivity = 1.0`으로 통일한다.** 예전엔 자본집약 업종의 안정성, 성장산업의
성장성에 1.3배 가중을 적용했었다. 그러나 이 업종 라벨은 큐레이션된 워치리스트 종목에만 붙어있고
(전종목은 DART 업종코드만 있는데, 지주회사 코드 하나가 여러 섹터로 갈리는 등 코드→섹터 매핑이
모호하다), 결과적으로 같은 업종이라도 워치리스트 종목만 가중돼 "워치 vs 비워치"가 다르게
채점되는 불일치를 낳았다(자동화 파이프라인 `automation/deterministic_scoring.py`의
`sector_sensitivity()`에서 이미 이 이유로 1.0으로 되돌렸다). 대화형 분석도 동일하게 sensitivity를
조정하지 않아야 같은 종목이 채팅 리포트와 대시보드에서 다른 점수로 보이지 않는다.

업종 정규화 자체는 이미 "업종중앙값(또는 대체 표본) 대비" 비교가 수행하므로, sensitivity 조정
없이도 핵심(동종기업 기준 상대평가)은 그대로 보존된다.

## 활동성(activity) 지표의 주의사항

`asset_turnover` 등은 financial-ratio-analyzer 주석대로 분기 누적치 기준이라 연환산이 아니다.
따라서 절대 수치 자체보다 **산업평균 대비 상대값**(`relative_favorability`)만 신뢰해서 판단할 것 —
동일 분기·동일 누적기준으로 target과 peer를 같은 방식으로 계산했으므로 상대비교는 유효하다.

## 계산 예시 (fixture 데이터 기준)

안정성 지표 3개의 `relative_favorability`가 각각 1.807 / 1.079 / 1.083이면(모두 [0.2,5.0] 안이라
클램프 영향 없음): `geometric_mean = (1.807×1.079×1.083)^(1/3) ≈ 1.283`, `ln(1.283) ≈ 0.249`,
`score = 3 + 1.0×2.16×0.249 ≈ 3.5점`.

성장성 지표 3개가 1.318 / 2.445 / 4.300이면(역시 클램프 영향 없음) `geometric_mean ≈ 2.402`,
`ln(2.402) ≈ 0.877`, sensitivity=1.0이면 `score = 3 + 1.0×2.16×0.877 ≈ 4.9점`.

**지표 하나가 극단치인 경우(클램프가 실제로 작동하는 케이스)**: 전년 매출 기저가 거의 0인 종목이
성장률 지표 하나에서 `relative_favorability=47.8`(다른 두 지표는 1.2 / 1.1로 정상)이 나왔다면:
- 클램프 없이 그대로 기하평균하면 `(1.2×1.1×47.8)^(1/3) ≈ 3.98` → `score ≈ 3+2.16×ln(3.98) ≈ 5.0점`
  (극단치 지표 하나가 카테고리 전체를 "우수"로 오판시킴 — 41종목이 실제로 이렇게 허위 5.0점을 받았다)
- [0.2,5.0]로 클램프하면(=코드의 실제 동작) `(1.2×1.1×5.0)^(1/3) ≈ 1.876` → `score ≈ 3+2.16×ln(1.876) ≈ 4.4점`
  (여전히 양호하지만 극단치 하나에 지배되지 않은, 더 신뢰할 수 있는 점수)

극단값(5.0)이 나오면(클램프 이후에도) report-formatter가 입력값과 무관하게 자동으로 "재검토 권장"
배너를 붙인다 — LLM이 별도로 플래그를 챙기지 않아도 된다(A9 확정 정책).

## 리포트 서술 요구사항

- 카테고리별로 사용한 지표, `comparison_basis`(industry_average/market_average_fallback/unavailable),
  sensitivity 조정 여부와 이유를 명시
- `comparison_basis: "unavailable"`이면 점수 자체를 매기지 말고 절대 수치만 서술 (비교 기준이
  없는데 점수를 매기면 근거 없는 숫자가 된다)
