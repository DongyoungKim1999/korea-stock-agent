# 업종분류 참고자료

## 사용하는 두 가지 업종분류 체계

이 프로젝트는 서로 다른 목적으로 두 가지 업종분류를 함께 쓴다 — 하나로 통일하지 않는 이유는
각각 얻는 방법의 비용/용도가 다르기 때문이다.

| 체계 | 출처 | 용도 | 얻는 방법 |
|---|---|---|---|
| DART 표준산업분류코드(`induty_code`) | DART `company.json` | 리포트에 "업종: OOO"로 표시, LLM의 업종 특성 판단(자본집약/성장산업 여부) 근거 | dart-financial-fetcher |
| KRX 업종분류 | pykrx `get_market_sector_classifications` | 동일업종 **피어 목록**을 한 번의 호출로 대량 확보 | financial-ratio-analyzer 실행 전 fundamental-analyst가 직접 호출 |

DART 코드는 5자리 숫자(KSIC 기반)라 세분류가 너무 잘게 쪼개져 있어 "동일업종 최소 5개사"
표본을 안정적으로 채우기 어렵다. KRX 업종분류는 대분류(전기전자/화학/운수장비 등)라 표본 확보에
더 적합하다 — 그래서 **피어 탐색은 KRX 분류로, 업종 성격 서술은 DART 코드로** 역할을 나눈다.

## A6: 동일업종 표본 부족 시 처리 (확정)

리뷰 체크포인트에서 확정된 정책: **표본 5개사 미만이면 시장평균으로 대체**한다.

1. KRX 업종분류 조회 자체가 실패 → 비교 없이 진행 (`comparison_basis: "unavailable"`)
2. 조회는 성공했지만 동일업종 종목이 5개사 미만 → **같은 호출로 이미 받아온 전체 목록**(업종
   무관)에서 추가로 표본을 채워 5개 이상으로 만든다 (`comparison_basis: "market_average_fallback"`).
   추가 API 호출 없이 이미 가진 데이터로 처리하므로 C6(호출한도) 부담이 없다
3. 최종 리포트에는 어느 경우든 `comparison_basis` 값을 그대로 노출해 사용자가 비교 기준을
   알 수 있게 한다 — "산업평균"이라고 뭉뚱그려 말하지 않는다

절차의 나머지 세부사항(피어를 몇 개 뽑는지, 시가총액 우선순위 등)은
`financial-ratio-analyzer`의 SKILL.md "실행 전 준비" 절을 따른다.

## 금융업 관련 주의

은행/보험/증권 등은 재무제표 구조 자체가 일반 제조업과 달라(예: 유동자산/유동부채 구분이
없음) `financial-ratio-analyzer`의 활동성·일부 안정성 지표가 `null`로 나올 수 있다. 이는
버그가 아니라 업종 특성이므로, 리포트에 "금융업 특성상 일부 지표 산출불가"로 명시하고 산출된
지표만으로 서술한다.

## 손익계산서 sj_div가 회사마다 다름 (실제 확인된 이슈)

업종과 무관하게, 회사에 따라 손익 계정을 별도 손익계산서(`sj_div="IS"`)로 내는 곳과 포괄손익계산서
하나(`sj_div="CIS"`)에 매출액·영업이익·순이익까지 전부 담아 내는 곳이 섞여 있다(예: 삼성전자는
"IS", SK하이닉스·KB금융·NAVER는 "CIS"만 존재 — 실제 DART 응답으로 확인됨). 은행 등 금융업만의
문제가 아니라 일반 제조·인터넷 기업에도 흔하다. `financial-ratio-analyzer`의 손익 계정 조회는
`("IS","CIS")` 둘 다 확인하도록 되어 있으니 이 문서와 다른 결과가 나오면 그게 먼저 의심 대상이다.
